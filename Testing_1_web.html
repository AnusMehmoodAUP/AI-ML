Module 01 · Mathematics

Linear Algebra

Vectors — The Building Block of Data

A vector is an ordered list of real numbers. In machine learning, every data point is a vector: a patient record, a word embedding, an image (flattened), or a set of sensor readings. A column vector of n elements lives in ℝⁿ (n-dimensional real Euclidean space).

v = [v₁, v₂, ..., vₙ]ᵀ ∈ ℝⁿ (column vector notation)

Core Vector Operations

  • Addition: (a + b)ᵢ = aᵢ + bᵢ — element-wise; geometrically the tip-to-tail rule
  • Scalar multiplication: (cv)ᵢ = c·vᵢ — stretches or flips the vector
  • Dot product: a·b = Σᵢ aᵢbᵢ = ‖a‖‖b‖cos(θ) — scalar measuring alignment
  • L2 Norm (Euclidean length): ‖v‖₂ = √(Σ vᵢ²) — geometric distance from origin
  • L1 Norm (Manhattan): ‖v‖₁ = Σ |vᵢ| — sum of absolute values; induces sparsity in optimisation
  • L∞ Norm: ‖v‖∞ = max|vᵢ| — maximum absolute component
  • Unit vector: v̂ = v / ‖v‖ — normalised to length 1; captures direction only
  • Cosine similarity: cos(θ) = (a·b)/(‖a‖‖b‖) ∈ [−1,1] — measures angle between vectors, not magnitude
Dot product = 0 ⟹ orthogonal (perpendicular). cos(θ) = 1 ⟹ identical direction. cos(θ) = −1 ⟹ opposite direction. Attention mechanisms compute dot products between query and key vectors: high dot product = high relevance.

Projection

The projection of a onto b: proj_b(a) = (a·b / ‖b‖²) b. This computes "how much of a lies along the direction of b." Used in Gram-Schmidt orthogonalisation and least-squares solutions.

Cross Product (3D only)

a × b gives a vector perpendicular to both a and b. ‖a × b‖ = ‖a‖‖b‖sin(θ). Direction follows right-hand rule. Rarely needed in ML; appears in 3D geometry and physics simulations.

In ML, always check whether cosine similarity or Euclidean distance is more appropriate for your task. For embeddings (word vectors, sentence embeddings), cosine similarity is usually preferred because it ignores magnitude differences due to document length or frequency.

Matrices — Linear Transformations in Data

A matrix A ∈ ℝ^(m×n) is a 2D array with m rows and n columns. Matrices encode: linear transformations (rotations, scalings, projections), datasets (rows = samples, columns = features), and neural network weight layers.

A = ⎡a₁₁ a₁₂ ··· a₁ₙ⎤ ⎢a₂₁ a₂₂ ··· a₂ₙ⎥ ∈ ℝ^(m×n) ⎣aₘ₁ aₘ₂ ··· aₘₙ⎦

Matrix Multiplication — The Core Operation

For A ∈ ℝ^(m×k) and B ∈ ℝ^(k×n), the product C = AB ∈ ℝ^(m×n) where Cᵢⱼ = Σₖ Aᵢₖ Bₖⱼ (dot product of row i of A with column j of B). Inner dimensions must match.

C[i][j] = (row i of A) · (column j of B) Complexity: O(m·k·n) — very expensive for large matrices
Matrix multiplication is NOT commutative: AB ≠ BA in general. But it IS associative: (AB)C = A(BC). It IS distributive: A(B+C) = AB+AC. The inner dimensions MUST match: (m×k)(k×n) = (m×n).

Key Operations

  • Transpose: (Aᵀ)ᵢⱼ = Aⱼᵢ; rule: (AB)ᵀ = BᵀAᵀ; (ABC)ᵀ = CᵀBᵀAᵀ
  • Trace: tr(A) = Σᵢ Aᵢᵢ = sum of diagonal = sum of eigenvalues; tr(AB) = tr(BA)
  • Determinant: Scalar encoding if A is invertible and how it scales area/volume. det(AB) = det(A)det(B). det(Aᵀ) = det(A). If det(A) = 0 → singular, not invertible.
  • Inverse: A⁻¹ exists iff A is square AND det(A) ≠ 0. AA⁻¹ = I. (AB)⁻¹ = B⁻¹A⁻¹. Solve Ax=b as x = A⁻¹b — but in practice, use LU decomposition, not explicit inversion.
  • Pseudoinverse A⁺: Generalises inverse to non-square/singular matrices. A⁺ = VΣ⁺Uᵀ where Σ⁺ replaces non-zero σᵢ with 1/σᵢ. Gives minimum-norm least-squares solution.
  • Hadamard product (⊙): Element-wise multiplication: (A⊙B)ᵢⱼ = AᵢⱼBᵢⱼ. Used in LSTM gates, attention masks.

Vector Spaces, Subspaces & The Four Fundamental Subspaces

A vector space V over ℝ is a set closed under vector addition and scalar multiplication. The most common is ℝⁿ. Understanding the structure of A tells you everything about solving Ax = b.

Essential Definitions

  • Linear combination: c₁v₁ + c₂v₂ + ... + cₖvₖ for scalars cᵢ and vectors vᵢ
  • Span: All possible linear combinations of a set of vectors
  • Linear Independence: Vectors {v₁,...,vₖ} are independent if c₁v₁+...+cₖvₖ = 0 implies all cᵢ = 0. No vector is redundant.
  • Basis: A minimal set of linearly independent vectors that span the space. Standard basis of ℝ³: {e₁=[1,0,0]ᵀ, e₂=[0,1,0]ᵀ, e₃=[0,0,1]ᵀ}
  • Dimension: The number of vectors in any basis of a space — unique for each space
  • Rank: rank(A) = number of linearly independent columns = number of linearly independent rows = dimension of column space. Full rank: rank = min(m,n)

The Four Fundamental Subspaces of A ∈ ℝ^(m×n)

SubspaceDefinitionDimensionMeaning
Column space C(A)All Ax — range/imager = rank(A)Which b's can be reached by Ax=b
Null space N(A)All x: Ax = 0n − rSolutions lost/collapsed by A
Row space C(Aᵀ)All AᵀyrInput subspace not collapsed
Left null space N(Aᵀ)All y: Aᵀy = 0m − rOutput directions orthogonal to range
Rank-Nullity Theorem: rank(A) + nullity(A) = n (number of columns). This is why if features are linearly dependent (redundant), the null space is non-trivial — the system has infinitely many solutions. PCA explicitly finds the subspace of maximum variance.

Solving Linear Systems Ax = b

  • Unique solution: A is square and full rank (det ≠ 0). x = A⁻¹b
  • No solution: b ∉ column space of A (overdetermined, m > n, inconsistent)
  • Infinitely many solutions: Non-trivial null space (underdetermined, m < n). General solution: x = xₚ + xₙ (particular + null space component)
  • Least squares: When no exact solution, minimise ‖Ax−b‖². Normal equations: AᵀAx = Aᵀb → x = (AᵀA)⁻¹Aᵀb = A⁺b

Eigenvalues, Eigenvectors & Decompositions

For a square matrix A, eigenvector v is a special direction that A only stretches (or flips) without rotating: Av = λv where λ is the eigenvalue (scaling factor). Every square matrix has n eigenvalues (counting multiplicity) over ℂ.

Av = λv ⟺ (A − λI)v = 0 ⟺ det(A − λI) = 0 (characteristic polynomial)

Eigendecomposition (Spectral Decomposition)

If A has n linearly independent eigenvectors, it is diagonalisable: A = QΛQ⁻¹ where Q = [v₁|v₂|...|vₙ] (eigenvectors as columns) and Λ = diag(λ₁,...,λₙ).

For real symmetric A (spectral theorem): A = QΛQᵀ where Q is orthogonal (QᵀQ = I). Eigenvalues are always real. Eigenvectors are mutually orthogonal. Extremely important — covariance matrices are always symmetric!

Powers: Aᵏ = QΛᵏQᵀ → very efficient computation Inverse: A⁻¹ = QΛ⁻¹Qᵀ (eigenvalues of inverse = 1/λᵢ)

Singular Value Decomposition (SVD)

SVD generalises eigendecomposition to any matrix A ∈ ℝ^(m×n), not just square:

A = UΣVᵀ where U ∈ ℝ^(m×m): left singular vectors (orthonormal columns) Σ ∈ ℝ^(m×n): diagonal with σ₁ ≥ σ₂ ≥ ... ≥ σᵣ > 0 (singular values) Vᵀ ∈ ℝ^(n×n): right singular vectors (orthonormal columns) Compact form (economy SVD): A = UᵣΣᵣVᵣᵀ (only r non-zero singular values)

Geometric Interpretation

SVD tells you: V rotates input space, Σ scales it along principal axes, U rotates output space. The singular values σᵢ are the "stretching factors" of the transformation A.

Applications of SVD in ML

ApplicationHow SVD is Used

The Eckart-Young theorem: Aₖ (rank-k truncated SVD) is the best rank-k approximation to A in both the Frobenius norm and the spectral norm. This is why PCA retaining top-k components is optimal under squared error.

Norms and Their Relationship to SVD

Spectral norm (operator norm): ‖A‖₂ = σ_max Frobenius norm: ‖A‖_F = √(Σ σᵢ²) = √tr(AᵀA) Nuclear norm (trace norm): ‖A‖_* = Σ σᵢ (convex surrogate for rank)

Principal Component Analysis (PCA) — Deep Dive

PCA finds the orthogonal directions of maximum variance in high-dimensional data, providing an optimal linear dimensionality reduction. It answers: "What are the most important directions in my data?"

Algorithm Step-by-Step

  1. Centre the data: X̃ = X − μ̄ (subtract mean from each feature)
  2. Compute covariance matrix: C = (1/(n−1)) X̃ᵀX̃ ∈ ℝ^(d×d)
  3. Eigendecompose: C = QΛQᵀ. Sort eigenvalues λ₁ ≥ λ₂ ≥ ... ≥ λ_d
  4. Select top-k components: W = [q₁,...,qₖ] (first k eigenvectors)
  5. Project: Z = X̃W ∈ ℝ^(n×k) — reduced representation
Explained variance ratio = λₖ / Σλᵢ Cumulative explained variance of top-k = (Σᵢ₌₁ᵏ λᵢ) / (Σᵢ λᵢ) Rule of thumb: retain enough components to explain 95% variance
PCA via SVD of X̃: X̃ = UΣVᵀ. Principal components = columns of V. Scores = U·Σ. Equivalent to eigendecomposition of covariance but numerically more stable. Use SVD in practice.

Limitations of PCA

  • Only captures linear structure — misses non-linear manifolds
  • Sensitive to outliers (which inflate variance)
  • Requires standardisation if features are on different scales
  • Components are global — not interpretable as individual features

Alternatives: Kernel PCA (non-linear via kernel trick), t-SNE (non-linear, preserves local structure, for visualisation), UMAP (preserves both local and global structure, faster than t-SNE), Autoencoders (deep non-linear dimensionality reduction).

Calculus for Machine Learning

Derivatives — The Language of Change

The derivative f′(x) = df/dx measures the instantaneous rate of change of f at x. Geometrically, it is the slope of the tangent line. Physically, it is the velocity if f is position. In ML, it tells us how the loss changes as we move a weight — the direction to nudge weights to reduce loss.

f′(x) = lim[h→0] (f(x+h) − f(x)) / h (formal definition)

Essential Derivative Rules

RuleFormulaML Use / Example
Power ruled/dx[xⁿ] = nxⁿ⁻¹d/dx[w²] = 2w → L2 regularisation gradient
Constantd/dx[c] = 0Bias doesn't affect other weights
Sum rule(f+g)′ = f′+g′Gradient of sum = sum of gradients
Product rule(fg)′ = f′g + fg′Derivatives in LSTM gate products
Quotient rule(f/g)′ = (f′g − fg′)/g²Softmax Jacobian derivation
Chain rule[f(g(x))]′ = f′(g(x))·g′(x)Backpropagation — the most important rule
Exponentiald/dx[eˣ] = eˣSigmoid: σ′ derived from this
Natural logd/dx[ln x] = 1/xCross-entropy loss gradient
Sigmoid σ(x)σ′(x) = σ(x)(1−σ(x))Output in [0,0.25] — causes vanishing gradient
ReLUd/dx[max(0,x)] = 0 (x<0), 1 (x>0)Constant gradient for x>0 — no vanishing!
Tanhd/dx[tanh x] = 1 − tanh²(x)Output in [0,1] — still saturates
The sigmoid derivative σ′(x) = σ(x)(1−σ(x)) reaches a maximum of only 0.25 when x=0 and approaches 0 for large |x|. Multiplied across many layers, this causes the vanishing gradient problem. ReLU derivative is exactly 1 for positive inputs — this is why ReLU largely solved the problem for deep networks.

Higher-Order Derivatives

  • Second derivative f″(x): Rate of change of slope — measures curvature. f″ > 0: convex (bowl shape), f″ < 0: concave (hill shape).
  • Critical points: f′(x) = 0. Second derivative test: f″ > 0 → local min; f″ < 0 → local max; f″ = 0 → inconclusive (saddle?).
  • Saddle points: Points where f′ = 0 but not a local extremum. Very common in high-dimensional loss landscapes of neural networks. Not a serious problem in practice — SGD escapes them.

Chain Rule — The Engine of Backpropagation

The chain rule computes derivatives through composite functions. It is the single most important calculus result in all of machine learning — every neural network training algorithm is an application of it.

The Rule

If y = f(g(x)), then: dy/dx = (dy/dg) · (dg/dx) = f′(g(x)) · g′(x) For a chain z = h(f(g(x))): dz/dx = (dz/dh) · (dh/df) · (df/dg) · (dg/dx)

Intuition: Error Propagation

Think of each function as a "telephone relay." The rate at which z changes with x = the rate z changes with h × the rate h changes with f × ... × the rate g changes with x. Each local gradient is multiplied together to get the end-to-end gradient.

Chain Rule in a Neural Network Layer

Layer: h = σ(Wx + b), Loss = L(h) ∂L/∂W = (∂L/∂h) · (∂h/∂z) · (∂z/∂W) where z = Wx + b = δ · σ′(z) · xᵀ = (upstream gradient) × (local gradient) × (local Jacobian)
Backpropagation is NOT a separate algorithm — it IS the chain rule applied to a computational graph. PyTorch's autograd traces every operation, builds a computation graph, then applies the chain rule in reverse (backward pass) using stored intermediate values.

Gradients, Jacobians & Hessians

  • Partial derivative ∂f/∂wᵢ: Derivative w.r.t. one variable, holding others fixed. The "slice" of the gradient.
  • Gradient ∇f(w) ∈ ℝⁿ: Vector of all partial derivatives. Points in direction of steepest ascent. Gradient descent moves in direction −∇f.
  • Directional derivative: ∇_v f(w) = ∇f(w) · v̂ — rate of change in direction v̂. Maximum in direction of ∇f.
  • Jacobian J ∈ ℝ^(m×n): Matrix of partial derivatives for vector-valued f: ℝⁿ → ℝᵐ. Jᵢⱼ = ∂fᵢ/∂xⱼ. The chain rule for vectors: ∂z/∂x = (∂z/∂y)(∂y/∂x) = J_zy · J_yx.
  • Hessian H ∈ ℝ^(n×n): Matrix of second-order partials: Hᵢⱼ = ∂²f/∂wᵢ∂wⱼ. Symmetric. Positive definite at minimum, negative definite at maximum, indefinite at saddle. Newton's method uses H⁻¹∇f for faster convergence.

Gradient Descent & Optimisation Theory

Gradient descent iteratively moves in the direction of steepest descent to minimise a loss function. It is the backbone of all neural network training.

Learning Rate — The Most Critical Hyperparameter

Too large η: overshoots minimum, loss oscillates or diverges Too small η: extremely slow convergence, may get stuck Ideal η: fast convergence to good minimum Rule for L-smooth convex: η < 2/L guarantees convergence (L = Lipschitz constant of gradient)

Probability & Information Theory Essentials

Probability and information theory underpin every probabilistic ML model, loss function design, and model evaluation.

Core Probability Concepts

  • Probability distribution P(X): Assigns probabilities to outcomes. Discrete: PMF; Continuous: PDF. Must sum/integrate to 1.
  • Joint distribution P(X,Y): Probability of X and Y occurring together
  • Marginal: P(X) = Σ_Y P(X,Y) — "integrate out" Y
  • Conditional: P(X|Y) = P(X,Y)/P(Y) — probability of X given Y is known
  • Independence: X⊥Y iff P(X,Y) = P(X)P(Y)
  • Bayes' theorem: P(Y|X) = P(X|Y)P(Y) / P(X) = likelihood × prior / evidence
  • Expectation: E[X] = Σ x·P(x); E[f(X)] = Σ f(x)P(x)
  • Variance: Var(X) = E[(X−μ)²] = E[X²] − E[X]²

Key Distributions in ML

Gaussian N(μ,σ²)(2πσ²)^(-½) exp(−(x−μ)²/2σ²)Weight init, noise modelling, VAE latent space
Bernoullipˣ(1−p)^(1−x)Binary classification output

Information Theory

Self-information: I(x) = −log₂ P(x) [bits] — how surprising event x is Entropy: H(X) = −Σ P(x) log P(x) — average surprise; measures uncertainty Cross-entropy: H(P,Q) = −Σ P(x) log Q(x) — H(P) + KL(P‖Q) KL divergence: KL(P‖Q) = Σ P(x) log[P(x)/Q(x)] — how much P differs from Q; always ≥ 0 KL = 0 iff P = Q; not symmetric: KL(P‖Q) ≠ KL(Q‖P) Classification loss = cross-entropy = −Σ yᵢ log ŷᵢ Minimising cross-entropy loss = minimising KL divergence from predictions to true labels
L2 regularisation = MAP estimation with Gaussian prior on weights. L1 regularisation = MAP estimation with Laplace prior. This probabilistic view explains why these regularisers work: they encode prior beliefs that weights should be small.

Object-Oriented Programming (OOP) — Deep Dive

OOP organises code around objects — instances of classes that bundle state (attributes) and behaviour (methods). Python's entire ML ecosystem (PyTorch, sklearn, Keras) is built on OOP patterns.

The Four Pillars — With ML Examples

Encapsulation

Bundle data + methods; hide internal state. Python convention: _protected (one underscore), __private (name mangling). sklearn's estimators hide complex algorithm internals behind .fit()/.predict().

Inheritance

Child class inherits parent's attributes and methods. PyTorch: all models subclass nn.Module. sklearn: all classifiers subclass BaseEstimator + ClassifierMixin. Enables code reuse and polymorphism.

Polymorphism

Same interface, different implementations. .fit() works the same way on LinearRegression, RandomForest, SVM. Enables sklearn pipelines — swap models without changing the training code.

Abstraction

Hide complex implementation behind clean interface. Abstract base class (ABC) forces subclasses to implement required methods. PyTorch's nn.Module requires .forward() to be defined.

Python-Specific OOP Features

  • __init__: Constructor — initialises instance state when object created
  • self: Reference to current instance passed implicitly to all instance methods
  • @property: Define computed attributes with getter/setter without changing interface
  • @staticmethod: Method that doesn't access self or cls — utility function in class namespace
  • @classmethod: Method receiving cls — used for alternative constructors (e.g., Model.from_pretrained())
  • Dunder methods: __str__, __repr__, __len__, __eq__, __add__, __call__ — define how operators and builtins behave on objects. nn.Module uses __call__ to run forward() with hooks.
  • __call__: Makes an object callable like a function — model(x) internally calls model.__call__(x) which runs forward() and applies hooks
  • MRO (Method Resolution Order): C3 linearisation — defines lookup order for multiple inheritance. class C(A,B): MRO = C → A → B → object
  • __slots__: Restrict instance attributes to fixed set, use array instead of __dict__ — saves 40-50% memory. Useful for many small objects.
  • Mixins: Small classes providing specific functionality via multiple inheritance. LogMixin, SerializableMixin. Common in ML frameworks.

Descriptors (How Properties Work)

Objects implementing __get__, __set__, __delete__ are descriptors. They run custom code on attribute access. @property, @classmethod, @staticmethod are all descriptors. Used to implement lazy evaluation, type checking, and caching in ML code.

PyTorch design pattern: class MyModel(nn.Module): def __init__(self): super().__init__(); self.layer = nn.Linear(10,5). def forward(self,x): return self.layer(x). When you write model(x), Python calls __call__ which handles gradients, hooks, and then calls forward(x).

Memory, Concurrency & Python Internals

The Global Interpreter Lock (GIL)

CPython's GIL allows only one thread to execute Python bytecode at a time. Consequence: Python threads can't achieve true CPU parallelism for compute-heavy code. Solutions:

  • I/O-bound parallelism: Use threading or asyncio — GIL is released during I/O waits
  • CPU-bound parallelism: Use multiprocessing — each process has its own GIL
  • NumPy/PyTorch: Release GIL during C-level computation — threads work!
  • DataLoader workers: num_workers > 0 uses multiprocessing for data loading

Memory Management

  • Reference counting: Objects are freed when reference count drops to 0
  • Cycle collector: Handles circular references that ref counting misses
  • Generators: Produce values lazily — O(1) memory vs O(n) for full list
  • weakref: Reference that doesn't prevent garbage collection — avoids memory leaks in caches and observer patterns

Decorators

A decorator wraps a function to modify or extend its behaviour without changing source code. Essential pattern in ML frameworks:

@torch.no_grad() # disables gradient tracking for inference @functools.lru_cache(maxsize=128) # memoises function calls @property # creates computed attributes @staticmethod # removes self parameter def decorator(func): def wrapper(*args, **kwargs): # pre-processing result = func(*args, **kwargs) # post-processing return result return wrapper

Context Managers

Core ML Algorithms — In Depth

Linear Regression

Model: ŷ = wᵀx + b. Assumes linear relationship. Loss = MSE = (1/n)Σ(yᵢ − ŷᵢ)².

Analytical solution (Normal Equation): w = (XᵀX)⁻¹Xᵀy Gradient: ∂MSE/∂w = (2/n)Xᵀ(Xw−y) Limitation: (XᵀX) inversion is O(d³) — impractical for d > ~10,000 Alternative: gradient descent O(nd) per step
Ridge regression (L2 regularised): w = (XᵀX + λI)⁻¹Xᵀy. Adding λI makes the matrix positive definite and invertible even when XᵀX is singular (multicollinear features). This is one of the most practically important ML formulas.

Logistic Regression — Binary Classification

Model: P(y=1|x) = σ(wᵀx+b) = 1/(1+e^(−wᵀx−b)) Loss: Binary Cross-Entropy = −[y log σ(z) + (1−y) log(1−σ(z))] Gradient: ∂L/∂w = (1/n) Xᵀ(σ(Xw)−y) ← elegant: prediction − label Decision boundary: wᵀx + b = 0 (hyperplane in feature space)

Despite the name, logistic regression is a linear classifier — the decision boundary is a hyperplane. It's the simplest probabilistic classifier and a critical baseline.

Decision Trees

Recursively partition feature space with axis-aligned splits. At each node, choose feature and threshold to maximise information gain.

Information Gain = H(parent) − Σ (|child|/|parent|) H(child) Entropy: H(S) = −Σ pᵢ log₂ pᵢ Gini impurity: G(S) = 1 − Σ pᵢ² (slightly faster to compute, similar results) Depth d tree can express 2^d leaf regions. Unpruned trees overfit: train accuracy ≈ 100%, test much lower.

Random Forest — Ensemble Bagging

Algorithm: 1. For each of B trees: a. Bootstrap sample D_b ⊂ D (sample n rows WITH replacement) b. At each split: consider only random subset of √d features c. Grow tree fully (max depth) 2. Predict: ŷ = majority vote (classification) or mean (regression) Why it works: Decorrelated trees reduce variance without increasing bias. Out-of-bag (OOB) error: ~37% of data never sampled → free validation estimate.

Gradient Boosting (GBM, XGBoost, LightGBM)

Additive ensemble: each new tree fits the residuals (pseudo-residuals = negative gradient of loss) of the previous ensemble. Builds trees sequentially, unlike Random Forest's parallel approach.

F_m(x) = F_{m-1}(x) + η · h_m(x) where h_m fits ∂L/∂F_{m-1} XGBoost adds: L2 regularisation on leaf weights + 2nd order (Hessian) approximation LightGBM: Histogram-based splits + leaf-wise growth → much faster
Gradient boosting typically outperforms random forests on tabular data. Rule of thumb: for structured/tabular data, use XGBoost or LightGBM; for images/text/sequences, use deep learning.

Support Vector Machine (SVM)

Hard margin: max 2/‖w‖ subject to yᵢ(wᵀxᵢ+b) ≥ 1 Soft margin: min ½‖w‖² + C·Σξᵢ subject to yᵢ(wᵀxᵢ+b) ≥ 1−ξᵢ Dual form: max Σαᵢ − ½ΣΣ αᵢαⱼyᵢyⱼxᵢᵀxⱼ → replace xᵢᵀxⱼ with K(xᵢ,xⱼ) Kernel trick: K(x,z) = φ(x)ᵀφ(z) without explicitly computing φ(x) RBF kernel: K(x,z) = exp(−γ‖x−z‖²) — infinite-dimensional feature space!

k-Nearest Neighbors (kNN)

Non-parametric, lazy learner. At prediction time, find k nearest training points by distance, output majority class (classification) or mean (regression). No training phase, but O(n·d) prediction cost. Always normalise features — otherwise features with large ranges dominate distance.

Naive Bayes

P(y|x) ∝ P(y) · Π P(xᵢ|y) (conditional independence assumption) Gaussian NB: P(xᵢ|y) = N(xᵢ; μᵢy, σ²ᵢy) Multinomial NB: P(xᵢ|y) ∝ count(xᵢ,y) — ideal for text (word counts) Laplace smoothing: add α to all counts to avoid zero probabilities

Bias-Variance Tradeoff, Regularisation & Model Selection

The Bias-Variance Decomposition

E[(y−f̂(x))²] = Bias²[f̂(x)] + Var[f̂(x)] + σ²_noise Bias = E[f̂(x)] − f(x) — systematic error from wrong assumptions Variance = E[(f̂(x) − E[f̂(x)])²] — sensitivity to training data fluctuations Noise = irreducible error from label noise
  • High bias (underfitting): Too simple model, misses true patterns. Symptoms: low training accuracy, low test accuracy. Fix: more complex model, more features, more capacity.
  • High variance (overfitting): Memorises training data, doesn't generalise. Symptoms: high training accuracy, much lower test accuracy. Fix: regularisation, more data, dropout, simpler model, ensembling.
The bias-variance tradeoff is not always a tradeoff in deep learning: "double descent" shows that as model size increases past interpolation threshold, test error can decrease again. Very large overparameterised models generalise well — this contradicts classical ML intuition.

Handling Missing Values

  • Deletion: Drop rows/columns with NaN. Risk: introduces bias if data not missing at random.
  • Mean/Median/Mode imputation: Simple, but reduces variance and ignores relationships.
  • Model-based imputation: Predict missing values using other features (KNN imputer, iterative imputer).
  • Indicator variable: Add binary "was_missing" column. Let model learn the pattern of missingness.
  • MCAR/MAR/MNAR: Missing Completely At Random / At Random / Not At Random — determines which imputation strategy is valid.

Module 05 · Deep Learning

Deep Learning

Neural Networks — Architecture & Computation

A neural network is a function approximator built by composing layers of linear transformations and non-linear activations. The Universal Approximation Theorem states that a sufficiently wide single-hidden-layer network can approximate any continuous function — but "sufficiently wide" may be exponential in input dimension. Depth provides exponential expressivity more efficiently.

Layer computation: h = activation(Wx + b) Forward pass of L-layer net: z₁ = W₁x + b₁; h₁ = σ(z₁) z₂ = W₂h₁ + b₂; h₂ = σ(z₂) ... ẑ = W_L h_{L-1} + b_L; ŷ = softmax(ẑ) (for classification)

Dying ReLU: if a neuron receives only negative inputs, its gradient is permanently 0 — it never updates. Caused by too-large learning rate or bad initialisation. Leaky ReLU, ELU, or careful initialisation prevents this. With BatchNorm + ReLU, dying ReLU is rare in practice.

Backpropagation — The Complete Algorithm

Forward Pass: Compute Predictions

For each layer l = 1,...,L: zˡ = Wˡ hˡ⁻¹ + bˡ (pre-activation) hˡ = σ(zˡ) (post-activation) h⁰ = x (input) Compute loss: L = loss(h^L, y)

Backward Pass: Compute Gradients via Chain Rule

Output layer: δᴸ = ∂L/∂zᴸ = ∇_ŷL ⊙ σ′(zᴸ) (⊙ = element-wise) For l = L−1,...,1 (propagate backwards): δˡ = ((Wˡ⁺¹)ᵀ δˡ⁺¹) ⊙ σ′(zˡ) Gradients: ∂L/∂Wˡ = δˡ (hˡ⁻¹)ᵀ ∂L/∂bˡ = δˡ

Weight Update

Wˡ ← Wˡ − η · ∂L/∂Wˡ bˡ ← bˡ − η · ∂L/∂bˡ
The δˡ term is the "error signal" at layer l. It combines the upstream error from deeper layers with the local derivative of the activation function. This is why dead neurons (σ′ = 0 everywhere) are catastrophic — they block all gradient flow backwards through them.

CNNs, RNNs & Key DL Architectures

Convolutional Neural Networks (CNNs)

CNNs exploit spatial structure through weight sharing — the same filter is applied at every location. Key inductive biases: translation equivariance (feature detector works anywhere) and locality (nearby pixels are more related).

Convolution: (I ★ K)[i,j] = Σ_m Σ_n I[i+m, j+n] · K[m,n] Output spatial size: ⌊(n + 2p − f)/s⌋ + 1 where n=input size, p=padding, f=filter size, s=stride Parameters in conv layer: f×f×C_in × C_out + C_out (biases) Depthwise separable conv (MobileNet): Standard: f×f×C_in×C_out params Depthwise: f×f×C_in + C_in×C_out params → ~8x reduction for f=3

Residual Connections — Why They Work

Standard: h = F(x) Residual: h = F(x) + x (identity skip connection) Gradient of residual block: ∂L/∂x = ∂L/∂h · (∂F/∂x + I) The "+I" ensures gradient never vanishes — identity path always carries gradient regardless of F′s behaviour. This allows training 1000+ layer networks.

RNNs and Sequence Models

RNN: hₜ = tanh(Wₕhₜ₋₁ + Wₓxₜ + b) BPTT: ∂L/∂h₁ = ∂L/∂hₜ · (Wₕ)^(t-1) → vanishing gradient for t-1 > ~10 LSTM gates (each a sigmoid → [0,1]): fₜ = σ(Wf[hₜ₋₁;xₜ] + bf) (forget gate: discard old memory?) iₜ = σ(Wᵢ[hₜ₋₁;xₜ] + bᵢ) (input gate: write new memory?) g̃ₜ = tanh(Wg[hₜ₋₁;xₜ] + bg) (candidate memory) cₜ = fₜ⊙cₜ₋₁ + iₜ⊙g̃ₜ (cell state: long-term memory) oₜ = σ(Wo[hₜ₋₁;xₜ] + bo) (output gate: expose memory?) hₜ = oₜ ⊙ tanh(cₜ) (hidden state)
LSTM's key insight: the cell state cₜ is updated via addition (not multiplication through tanh), creating a "gradient highway." The forget gate can be ≈1, letting gradients flow unchanged across many timesteps. This solved the vanishing gradient problem for sequences.

Dropout

During training: independently zero each neuron output with probability p (inverted dropout: scale by 1/(1−p) so expected value unchanged). Prevents co-adaptation of neurons — each neuron must be useful alone. Effectively trains an ensemble of 2^n sub-networks. Disabled at inference (deterministic). p = 0.1–0.2 for transformers, 0.5 for MLPs.

Transfer Learning

Take a model pre-trained on large dataset (ImageNet, C4, The Pile), freeze early layers (low-level features), fine-tune later layers on your task. Strategies: (1) Feature extraction: freeze all, only train head. (2) Fine-tuning: unfreeze top layers, small lr. (3) Full fine-tuning: unfreeze all, tiny lr. (4) Parameter-efficient fine-tuning (PEFT): LoRA, adapters — fine-tune <1% of parameters.

Module 06 · NLP

Natural Language Processing

Text Preprocessing & Tokenisation

Preprocessing Pipeline

  • Lowercasing: "Apple" → "apple". Risk: loses case-sensitive info (proper nouns, acronyms). Modern LLMs skip this.
  • Punctuation removal: Loses syntactic structure. Rarely done in modern NLP.
  • Stop word removal: Remove "the", "is", "at". Helps bag-of-words models; harmful for transformers that use context.
  • Stemming: Crude suffix removal (Porter, Snowball). "running" → "run", "studies" → "studi" (imprecise). No vocabulary lookup. Fast.
  • Lemmatisation: Morphological analysis using POS tags + vocabulary: "better" → "good", "running" → "run". Accurate but slow. WordNet-based (NLTK).

Word Embeddings — From Sparse to Dense

Bag of Words (BoW) and TF-IDF

BoW: document → sparse vector of word counts ∈ ℝ^|V| TF(t,d) = count(t,d) / total_tokens_in_d IDF(t) = log(N / df(t)) where N=num docs, df(t)=docs containing t TF-IDF(t,d) = TF(t,d) × IDF(t) Intuition: high score → word is frequent in THIS doc, rare in others → informative

Word2Vec — Neural Word Embeddings

Train a shallow neural network on a proxy task. The learned weight matrix becomes the word embeddings. Trained on billions of words in minutes.

CBOW: Context words → predict centre word [faster, slightly worse] Skip-gram: Centre word → predict context words [slower, better for rare words] Training objective (skip-gram with negative sampling): L = log σ(vₒᵀvᵢ) + Σ_{k~P_n} log σ(−vₖᵀvᵢ) (maximise similarity with true context, minimise with random "noise" words) Vector arithmetic (linear relationships learned): king − man + woman ≈ queen Paris − France + Germany ≈ Berlin

GloVe — Global Co-occurrence Statistics

Build co-occurrence matrix Xᵢⱼ = count(word i in context of word j) Loss: Σᵢⱼ f(Xᵢⱼ)(wᵢᵀw̃ⱼ + bᵢ + b̃ⱼ − log Xᵢⱼ)² f(x) = min(1, (x/xmax)^α) — weight function prevents frequent pairs dominating Captures global corpus statistics; faster convergence than Word2Vec

FastText — Subword Embeddings

Represents each word as bag of character n-grams (n=3–6). Word vector = sum of its n-gram vectors. Can represent OOV words. Handles morphologically rich languages (German, Arabic, Finnish). Shares n-gram representations across words: "run", "running", "runner" share subwords.

Contextual Embeddings — The Modern Standard

Static embeddings (Word2Vec, GloVe) give one vector per word regardless of context. "bank" (financial) and "bank" (river) get the same vector. Contextual embeddings (BERT, ELMo) produce different vectors depending on context.

The shift from static to contextual embeddings was one of the biggest advances in NLP. BERT representations encode syntactic, semantic, and coreference information all in a single vector. The same word in different sentences gets different, context-appropriate representations.

Module 07 · Transformers & LLMs

Transformers & Large Language Models

The Attention Mechanism — Full Derivation

Attention allows each position to directly attend to any other position. It replaces the sequential bottleneck of RNNs — an entire sequence is processed in O(1) layers (but O(n²) per layer).

Scaled Dot-Product Attention

Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V Dimensions: Q ∈ ℝ^(n×d_k) Queries — what am I looking for? K ∈ ℝ^(m×d_k) Keys — what do I have to offer? V ∈ ℝ^(m×d_v) Values — what content do I carry? Output ∈ ℝ^(n×d_v) For self-attention: Q = XWQ, K = XWK, V = XWV (same X, different projections) For cross-attention: Q = decoder state, K=V = encoder output Why divide by √d_k: Dot products grow as O(d_k): if d_k=64, σ(QKᵀ)≈64 Large values push softmax toward 0/1 (saturation) → tiny gradients Dividing by √d_k keeps variance of QKᵀ = 1 (if Q,K ~ N(0,1))

Multi-Head Attention — Parallel Specialisation

For h heads: headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV) WᵢQ∈ℝ^(d_model×d_k), etc. MultiHead(Q,K,V) = Concat(head₁,...,headₕ)Wᴼ d_k = d_v = d_model / h (split model dimension across heads) BERT-base: h=12, d_model=768, d_k=64 GPT-3: h=96, d_model=12288, d_k=128 Each head learns different attention pattern: Head 1: syntactic dependencies ("subject-verb agreement") Head 2: coreference ("he" → "John") Head 3: positional (attend to nearby tokens) Head 4: semantic similarity

Transformer Architecture — Complete Breakdown

Single Transformer Block

Input: x ∈ ℝ^(n×d_model) Sub-layer 1 (Multi-Head Self-Attention): x = x + Dropout(MultiHead(LN(x),LN(x),LN(x))) [Pre-LN] Sub-layer 2 (Feed-Forward Network): FFN(x) = GELU(xW₁ + b₁)W₂ + b₂ W₁ ∈ ℝ^(d_model × d_ff), W₂ ∈ ℝ^(d_ff × d_model) d_ff = 4·d_model (BERT/GPT); or d_ff = (8/3)·d_model (SwiGLU in LLaMA) x = x + Dropout(FFN(LN(x))) L blocks stacked. Final: LN(x) → projection to vocabulary

Positional Encoding

Sinusoidal (original Transformer): PE(pos, 2i) = sin(pos / 10000^(2i/d_model)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model)) → Deterministic; can extrapolate to unseen lengths Learned PE: trainable lookup table → better at training lengths, poor extrapolation RoPE (Rotary Position Encoding — LLaMA, GPT-NeoX): Encodes relative position in attention computation directly Rotates Q and K by angle proportional to position Better length extrapolation; widely used in modern LLMs ALiBi (Attention with Linear Biases — BLOOM, MPT): Subtract linear bias m·|i−j| from attention logits Simple; enables zero-shot extrapolation to longer contexts

Large Language Models — Pre-training to Alignment

Pre-training Objectives

Causal LM (GPT): L = −Σₜ log P(xₜ | x₁,...,xₜ₋₁; θ) Train on all tokens in sequence simultaneously (teacher forcing) At inference: generate autoregressively, sampling one token at a time Masked LM (BERT): L = −Σ_{i∈masked} log P(xᵢ | x\masked; θ) Mask 15% of tokens; 80% → [MASK], 10% → random, 10% → unchanged Bidirectional context; can't generate autoregressively Span corruption (T5): mask contiguous spans; predict them with decoder

RLHF — Reinforcement Learning from Human Feedback

Step 1: Supervised Fine-Tuning (SFT) Fine-tune pre-trained LLM on (prompt, ideal response) pairs from human demonstrators Step 2: Reward Model Training Collect human preference data: (prompt, responseA, responseB, preference) Train reward model: R(prompt, response) → scalar score Step 3: RL Fine-Tuning (PPO) Optimise: max_θ E[R(prompt, response)] − β·KL(π_θ || π_ref) KL penalty prevents model from drifting too far from original β balances reward and staying close to SFT model
DPO (Direct Preference Optimisation) — an alternative to RLHF: directly optimises on preference pairs without a separate reward model or RL. More stable, simpler. Loss: −log σ(β·log[π(y_w)/π_ref(y_w)] − β·log[π(y_l)/π_ref(y_l)]). Used in many modern fine-tunes.

RAG — Retrieval-Augmented Generation

Pipeline: 1. Indexing: Chunk documents → embed each chunk → store in vector DB 2. Retrieval: Query → embed → ANN search → top-k chunks 3. Generation: Concat(query, retrieved chunks) → LLM → answer Retrieval methods: Sparse (BM25): TF-IDF based; keyword matching; fast; no semantic understanding Dense (DPR): Bi-encoder; semantic matching; better recall Hybrid: Combine BM25 + dense; best of both Re-ranking: retrieve top-100 sparse → re-rank with cross-encoder → pass top-5 to LLM
